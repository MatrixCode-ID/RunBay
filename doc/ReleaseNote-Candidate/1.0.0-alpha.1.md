# RunBay 1.0.0-alpha.1

Date: 2026-10-24

## Summary
The first public alpha of RunBay, a small Windows tool to build and run your
applications from one place. Register apps, give them Build / Run / Build + Run
and custom PowerShell actions, and follow their live, colored output in a Full
window, a Compact list, or a floating icon. Coding agents can drive RunBay
through MCP (`RunBay.exe --mcp`), and RunBay updates itself from GitHub Releases.

## New features
- **Apps and actions**: apps with a name, group, icon (png/ico/svg), working
  directory, shell, and environment variables. Each app has Build, Run, and
  Build + Run actions plus custom actions, all backed by PowerShell scripts
  (`pwsh` 7, falling back to Windows PowerShell 5.1).
- **App editor**: a monospace script editor with *Open in external editor* and
  *Reload*, per-action working directory and environment overrides, and custom
  actions that can be added, reordered, and removed. Groups are created by typing
  a new name; apps are reordered with *Move up* / *Move down*.
- **Reliable runs**: every run lives in a Windows Job Object, so **Stop** ends the
  whole process tree, and a Run action stays active while the started application
  lives. No console windows are shown. Build + Run skips the Run step when the
  build fails.
- **When the app is still running**: per action choose *Ask* (stop and run, run in
  parallel, or cancel), *Reject*, *Restart*, or *Parallel*. Different apps always
  run in parallel.
- **Live output**: ANSI colors, auto-scroll that pauses when you scroll up, tabs
  for several active runs, and Stop, Copy all, Open log file, and Clear view. The
  on-screen buffer is limited (10,000 lines by default) while the log on disk
  stays complete.
- **Action History**: a flyout with the runs of every app, newest first, filtered
  by app, action, status, and source; selecting a run opens its log. Retention per
  action: off, last N runs, or forever.
- **Status at a glance**: Build and custom actions show a spinner, and an active
  Run action shows a steady green lamp. Badges appear on action buttons, app
  cards, output tabs, history, the tray icon, and the floating icon.
- **Three display modes**: Full (navigation, output, Action History), Compact (a
  small app list with an output popup per app), and Icon (a draggable floating
  icon in three sizes that snaps to the screen edge and opens a Compact popup).
  Always on top for Compact and Icon, and remembered positions per mode.
- **System tray**: switch modes, always on top, load with Windows, check for
  updates, and exit. Closing the window hides it to the tray; exiting with active
  runs asks to stop them first.
- **Load with Windows** reopens the last mode and position at sign-in. Only one
  instance runs per user; starting RunBay again focuses it.
- **Settings**: theme (Light / Dark / Follow Windows), floating icon size, output
  line limit, default retention and *when running* rule for new actions, auto
  update, and MCP access.
- **Custom data folder**: choose in Settings where RunBay keeps its settings, apps,
  scripts, and history, for example inside a Git repository. The choice applies
  after a restart; existing data is not moved.
- **MCP server for coding agents**: `RunBay.exe --mcp` is a stdio bridge to the
  running GUI (started on demand) over a named pipe restricted to the current
  user. Agents can list apps, run actions and wait for the result, read output,
  stop runs, edit apps, actions, and scripts, and change settings.
- **Agent safety**: *MCP access* is Off, Ask first (default: every change is
  confirmed in RunBay), or Unrestricted; removing an app is always confirmed.
  Agent runs are marked with the tertiary color, an agent icon, and a "by
  <agent>" chip, connected agents are shown on the tray and floating icon, and
  every agent change can be undone from a snackbar.
- **Automatic updates**: checks GitHub Releases on startup and every 6 hours,
  downloads in the background, verifies SHA-256, and installs only when you
  choose *Restart to update*. Versions can be skipped; manual checks work with
  auto update off.
- Script environment variables `RUNBAY_APP_ID`, `RUNBAY_ACTION_ID`,
  `RUNBAY_RUN_ID`, and `RUNBAY_APP_DIR`.
- Material 3 Expressive design, built with Rust and Slint, with the version shown
  in Full and Compact.

## Upgrade notes
- First release; nothing to migrate.
- Keep `RunBay.exe` in a folder you can write to: the `data/` folder is created
  next to it unless another data folder is chosen in Settings, and auto update
  replaces the executable in place.
- Build scripts must let their worker processes exit; for .NET use
  `dotnet build --disable-build-servers`, otherwise a finished build can stay
  marked as running.
